# Batch parse-only measurement protocol v2 (long timed blocks)

Frozen input to Task 02, 2026-10-23. This is a legacy batch baseline, not an editing result.

Root review on **2026-10-23** approved v2 and the current **1.3.0-alpha SDK**
reference only: process-mean A/A p95 absolute noise is small String **4.444 µs**,
small InputStream **3.304 µs**, large String **1.865 ms**, large InputStream
**2.404 ms**. See `baseline-v2-long-block-20261023/coordinator-review.json`,
which binds the reviewed summary hash. These describe measurement resolution,
not allowed regression percentages or evidence that a migrated parser is free.

## Protected objective

The user requires **no measurable slowdown beyond measurement noise** for both
`Markit.parse(String)` and `Markit.parse(InputStream)` with the same `-O2` build.
There is no permitted slowdown percentage. Warm editing improvements cannot
compensate for batch regressions. Protocol or input changes require a new
baseline and explicit coordinator review; do not retroactively loosen a gate.

## Fixed measurement boundary

- `batch_driver.cj` constructs Standard `Markit`, source strings and UTF-8 byte
  arrays before warmup. Every measured parse creates the real production session
  through the original public batch API; only the root child-count marker is
  consumed with `blackBox`. No renderer, source generation, file IO, process
  launch, forced GC or JSON output is inside the timed region.
- InputStream construction and the real parser's stream buffer/read/decode cost
  belong to that public API's measured operation. The in-memory stream returns
  up to the requested buffer size, including arbitrary Unicode byte splits.
- Small fixed-cost input contains heading, CRLF, Chinese, emoji, inline formats,
  link and a list. Large throughput input repeats that source 512 times,
  separated by CRLF. Exact bytes are generated by the frozen driver source.
- Monotonic `MonoTime` nanoseconds; 500 parses per small sample, eight per large
  sample. Each scenario warms both APIs for ten blocks. Twenty-one paired blocks
  alternate String/Stream ordering. Parse-only nanoseconds and MiB/s retain all
  raw samples; no outliers are deleted.
- Explicit heavy GC runs before each measured sample and after it. Post-sample
  GC elapsed time and the pre/post difference of the cumulative
  `getGCFreedSize()` counter are reported separately. The difference is
  a **managed heap reclamation/pressure proxy**, not total allocation, native allocation or
  guaranteed bytes allocated by that sample. Automatic GC counts are unavailable
  through this harness. Missing data stays unavailable, never zero. Earlier
  raw-counter runs retain the cumulative snapshots and are not used as
  per-sample allocation evidence; their raw source/executable remain preserved.
- Windows `GetProcessMemoryInfo` is sampled every 10ms for the child process.
  Working set is an RSS proxy. OS peak working set includes startup; steady
  working set is the median after the first SCENARIO marker, including warmup
  and GC. This is process-level memory, not per-parse attribution. Private commit
  and page faults are retained as additional proxies. Sampling can miss short
  spikes; OS peak counter provides the complementary peak observation.
  `GetSystemTimes` and `GetProcessTimes` record whole-process system busy CPU
  fraction and child CPU seconds outside the parser's timed regions. They do
  not assign individual pauses to specific external processes. A/B use the
  same 10ms observation frequency and process-launch overhead is never parsed
  as parser latency.
- `run-baseline.py` runs twelve identical frozen binaries (A/A calibration), saves
  executable/driver/dependency-manifest hashes, environment, complete stdout,
  stderr, RSS samples, all parse samples, descriptive bootstrap 95% intervals,
  and absolute A/A noise in nanoseconds. Formal calibration uses six balanced
  pairs of **process-block means**, matching the later stage-comparison unit.
  Per-sample intervals remain descriptive only. Exploratory/no quiet-window,
  fewer than six pairs, and directional A/A drift are refused by the classifier.
  Keep raw data and noisy runs.
- Actual local SDK is 1.3.0-alpha; this run does **not** prove minimum 1.1.0
  compatibility and does not change `cjc-version = "1.1.0"`.

## Environment control

Use the same machine, power configuration, CPU availability, installed compiler,
dependency resolution, source/input/driver hashes and `-O2` options for the
reference and candidate. Pause unrelated builds, tests and benchmarks during the
accepted measurement window; record any overlapping activity as a limitation.
No power/security/OS settings are changed by the harness. Parser construction,
cold executable startup and renderer cost are excluded from parse-only results;
they must be measured in separate columns when those paths are changed.

## Stage comparison and decision

1. Preserve this reference executable and its exact frozen `.a`/`.cjo` manifests.
   Rebuild the **same driver** with candidate production libraries, the same
   toolchain and explicit `-O2`; record candidate hashes. Do not compare to old
   stream benchmark reports or an executable of unknown build flags.
2. Run reference/candidate in alternating process order **A B B A**, repeating
   at least three cycles. Pair A/B process blocks in both orders. Each process
   emits the same 21 timed samples per size/API. Save every process result and
   dependency/environment identity. Repeat on uncontrolled interference.
3. Separately for each size/API, compute each process block mean, the six paired
   candidate-minus-reference differences, and a deterministic seeded bootstrap
   95% interval of those paired differences. Also show sample medians/p95,
   throughput, GC proxy and process RSS. Do not pool API modes or hide a small
   document regression behind large-document throughput.
4. Any positive 95% lower bound is a detected slowdown and **fails** the stage;
   no percentage allowance is applied. An interval overlapping zero indicates
   no statistically resolved direction at this sample count. If its width or
   upper bound exceeds the pre-recorded A/A process-mean noise envelope, classify it
   **inconclusive** and rerun under better-controlled conditions or with more
   process pairs. Never convert a noisy/inconclusive run to a pass.
5. A controlled comparison whose interval overlaps zero within the A/A noise
   envelope may report **no measurable slowdown at this protocol's resolution**,
   with the absolute noise/interval disclosed. This is not a claim of zero cost.
   A fully negative interval reports improvement. Coordinator reviews all four
   size/API results before releasing a successor stage.
6. Native allocation and automatic GC observability remain explicit gaps. Large
   RSS/GC-pressure increases require investigation; unavailable allocation must
   not be used to claim memory non-regression. Total allocation, exact GC count
   and minimum SDK compatibility need a supported environment/tool in later
   verification; no production instrumentation is added in Task 01.

## Reproduction

From repository root, after the current production `cjpm test --no-progress`
build has completed and no shared release output is being written:

To reproduce measurements of the preserved reference binary:

```powershell
& 'C:\Users\Shawn\AppData\Local\Programs\Python\Python311\python.exe' `
  .\tasklists\incremental-parsing\task01-performance\run-baseline.py `
  --executable .\tasklists\incremental-parsing\task01-performance\batch_driver_v2_long_block.exe `
  --output .\tasklists\incremental-parsing\task01-performance\baseline-<unique-run> --runs 12 `
  --quiet-window-note '<coordinator confirmed build/test pause; state residual activity>'
```

To rebuild from current release libraries, first invoke `build-driver.ps1`
with a fresh owned `-OutputDirectory`, then select its `batch_driver.exe`
explicitly in the measurement command. `build-driver.ps1` intentionally refuses to overwrite frozen libraries. Preserve
the existing reference directory; use a new owned run directory for future
candidate builds using `build-driver.ps1 -OutputDirectory <new-directory-inside-task01-performance>`.
For cross-stage comparison, use:

```powershell
& 'C:\Users\Shawn\AppData\Local\Programs\Python\Python311\python.exe' `
  .\tasklists\incremental-parsing\task01-performance\compare-builds.py `
  --reference <frozen-reference-exe> --candidate <candidate-exe> `
  --baseline-summary <accepted-baseline-summary.json> --output <new-output-directory> --cycles 3
```

The normal developer benchmark entry is
`cjpm bench --filter=EditingBatchBaselineBenchmarks`; it is a smoke/trend entry,
not a substitute for the raw paired protocol above.

## Separate 1.1.0 SDK record

First rebuild the production project and **all resolved dependencies** with the
explicit 1.1.0 SDK in an isolated target directory. Preserve that build command,
SDK environment and dependency/build logs. Never feed the current 1.3.0-alpha
`.a`/`.cjo` directory to a 1.1 baseline. After the coordinator supplies the actual
SDK and isolated release paths, the exact driver-build form is:

```powershell
& .\tasklists\incremental-parsing\task01-performance\build-driver.ps1 `
  -CompilerPath '<actual-1.1.0-sdk>\bin\cjc.exe' `
  -ExpectedCompilerVersion '1.1.0' `
  -ReleaseDirectory '<isolated-project-target>\release' `
  -OutputDirectory '.\tasklists\incremental-parsing\task01-performance\sdk110-reference'
```

The script records the selected compiler/version, explicit release directory,
driver source hash, real arguments and every copied library hash. It refuses a
1.1 expected version without an explicit release directory. A missing package,
compiler-version mismatch or failed compile is a failure, not fallback to PATH
`cjc` or the shared target. Run the generated `sdk110-reference\batch_driver.exe`
through `run-baseline.py --executable ...` in a new output directory with a
coordinated quiet window, after loading the 1.1 SDK's own environment script.
If that SDK requires runtime/DLL directories to be selected explicitly, pass
one or more `run-baseline.py --runtime-path '<actual-1.1-runtime-directory>'`
arguments. These are prepended only in the measured child process environment
and recorded; do not use a global SDK or security setting change. The process
must run against the same selected runtime used for both reference/candidate.
Environment metadata includes the selected build info,
in addition to ambient PATH tools, so ambient 1.3 must not be mistaken for the
selected 1.1 compiler. Reports use `measured_compiler` from the binary's build
info, not the ambient PATH `cjc` string. Stage comparison checks that selected
compiler identity and reuses the recorded runtime path for both binaries.
The 1.1 result needs separate root review and noise
calibration; it must never share the approved 1.3 reference label or comparison.

# Task06 concrete test provider

Owner: `task05_engine/session_checkpoint`. File: `markit/src/tests/unit/task06_inline_test_grammar.cj`. This is a small concrete grammar used by the main engine tests, not a parser framework or a built-in plugin migration. SOURCE_READY; its compilation and the real integration cases remain with owner02/main.

- Package-visible `Task06InlineGrammar` implements both `InlineParser` and `InlineEditingFacet`; `tryParse` and `parseAttempt` call the same private `task06Match` implementation, parameterized by byte reader, explicit length getter, semantic lookup and node factory. Editing uses `InlineAttemptContext` actual observed byte/semantic/length reads. Legacy uses bounded String indexing and the optional `legacyLookup` callback.
- `@body;` creates a typed node with `label=body`. Nested tokens balance naturally: `@outer @inner;;` creates one outer token with one typed child; the outer label retains its full raw body (`outer @inner;`). Odd backslash parity before an opener rejects it, and every inspected lookbehind byte is observed. The identity literal facet keeps literal backslashes unchanged; it does not impersonate Standard Markdown escaping.
- `@?key;` performs an actual semantic lookup. Missing keys return None, positive `StringEffectPayload` values become the label. Both outcomes are retained by the context's read evidence. The fixture's checkpoint payload freezes its last read evidence; restore validates owner/document/schema and restores that payload. The grammar is syntactically stateless, so syntax equivalence does not compare semantic-read versions and accidentally extend syntax propagation.
- `$` explicitly calls the length getter. Fewer than three remaining bytes returns None without fabricated suffix character reads; otherwise exactly three ASCII bytes form a token. This supplies the length-only None-to-success integration witness. Non-ASCII three-byte fragments refuse safely.
- `editingCalls` and `legacyCalls` are instance fields for focused assertions only. `failProbe=true` injects an allocator advance, root append, patch, block-context state and an effect with key `task06-failed-probe` only when a candidate returns None. The main engine's real parser-attempt scope must discard those writes while retaining read evidence.
- `returnsText=true` changes only the node factory in both paths: the same grammar produces a real successful TextNode with string/int/bool metadata. It is the concrete witness that parser-produced Text cannot be silently merged as identity literal text. The registered provider `owner` equals `ownerPlugin` (`task06-test`), preserving the existing registry contract.
- `Task06InlineNode` preserves label and normal children. `Task06InlineCodec` reconstructs its shallow typed state; `task06Codec()` additionally registers only the fixture's DocumentNode/TextNode base codec. It does not claim to preserve arbitrary plugin node subclasses.
- `recoverWindow` covers the actual old read footprints and the text change, then extends through a concrete candidate's balanced close/EOF when needed. It adds no fixed one-scalar following lookahead: that unrelated boundary touch would pull the next unchanged sibling into a retry. Actual failed opener/lookbehind evidence already supplies the needed recovery footprint. Ordinary candidate-free edits do not default to a full paragraph scan. Recovery endpoints are completed to UTF-8 scalar boundaries.
- `Task06LiteralFacet` implements identity decoding and a proven offset-preserving splice when the old payload covers the entire prior logical view. Its inverse raw projection is for the fixture's known ordered mapping, including gaps. It binary-searches resolved anchors in the view's own source epoch and checks both boundary affinities. Old views use `context.previous.atVersion(view.source.version)`; new node spans instead resolve birth anchors to the current block source and read actual rune coordinates. Synthetic/unproved inverse mappings return None.

Nested children are concrete typed syntax. Scheduling/reusing independent nested owners and effects remains the product engine's responsibility; the existence of this grammar alone is not proof that those integration gates passed. No new benchmark/counter/oracle infrastructure was added.

The identity literal facet explicitly proves `offsetsFollowLiteral(view)=true`. The separate `task06_nonidentity_literal.cj` implements `Task06EscapedLiteralFacet`, a concrete slash-removing test decoder with no offset-identity proof and `splice=None`. It shares only the provider's actual raw projection and base recovery helpers; the core must not split its decoded payload by raw byte offsets. Its actual behavioral case is owned by the main engine test owner, not claimed passed merely because this class was added.

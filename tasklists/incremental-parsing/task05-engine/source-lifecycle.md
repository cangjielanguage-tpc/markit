# Task05 source lifecycle implementation

Owner: `task05_engine/source_lifecycle`. Updated: 2026-10-23.

## Product changes and frozen integration API

- `core/source/editable_source.cj`: `EditableRopeStore.retainVersion(version)` returns an explicit, idempotently released `EditableSourceLease`. `pruneHistory()` deletes only the unleased prefix and returns its removed-batch count. `oldestAvailableVersion`, `retainedHistoryCount`, `retainedVersionCount`, and `historyCapacity` expose the concrete lifetime state. A freed birth epoch cannot be repinned or resolved through a warm cached projection. Cold resolution remains proportional to retained crossed deltas.
- History uses version-keyed entries instead of an ArrayList requiring prefix shifts. Pruning advances a monotonic floor, so it never scans all live raw nodes or rewrites anchors. The fixed 2048 projection slots are checked only when a prefix was actually freed. After capacity is over 64 and live entries fall below one quarter, a fresh map is populated from the remaining entries; this occasional compaction is amortized by released history and is not a per-edit whole-map clone.
- `core/session/persistent_cache.cj`: `SourceVersionRetention` adds a first-count `onRetain` hook. Retain/release hooks run before changing counts; a failed release leaves its lease active for retry. Current-version replacement acquires the new pin before releasing the old pin. Both concrete source and generic retention leases clear their owner reference after successful release, so keeping a released handle does not keep the source store alive.
- `core/session/editable_source_lifecycle.cj`: `EditableSourceLifecycle(store)` bridges the generic current/snapshot/cache retention tracker to real rope epoch leases. The bridge lives in session; source does not depend on session. Engine usage: `lifecycle.retention.setCurrent(version)`, `retain(birthEpoch)`, explicit `lease.release()`, then `lifecycle.pruneHistory()` only after all new active roots/checkpoints have their leases installed.
- `core/source/line_index.cj`: default batch mode retains its ArrayList append cost. `LineIndex.snapshot(): LineIndexSnapshot` keeps the buffer reference plus logical prefix length in O(1), and restore is O(1); only a subsequent append to a historical flat branch copies that prefix. Editing calls `enablePersistent()` on the initially empty index; explicit promotion of a populated flat index is O(N) once. Persistent append copies an O(log lines) AVL path, and its checkpoint/restore remain O(1). Restore returns to the snapshot's original flat/persistent representation even across a later promotion. Prior/future checkpoints and independently appended branches remain restorable. Legacy `lines()` remains an explicit O(N) export; `findByByteOffset` preserves first-match behavior, including shared endpoints and synthetic spans.
- `core/source/source_buffer.cj`: optional `editableSource: ?EditableSourceVersion` accepts an immutable rope view without appending or materializing the document. `byteAt` delegates to the new raw-byte `EditableRopeVersion.readByte`, and `slice` delegates to the rope. Explicit `materialize()` remains O(N). `bindEditableSource(version)` is view-only, requires the same document and a nondecreasing version, and clears the optional materialized cache. Append methods reject immutable views. A legacy mutable Node attached to a rebound buffer is not a persistent snapshot: published typed payloads must already be detached by the persistent codec.
- Raw provenance follow-up: `SourceBuffer.isBoundTo(SourceVersionIdentity)` checks only the immutable editable-view document/version binding. Append/synthetic buffers return false; no raw-text equality check or materialization is performed. This is the buffer-side fact consumed by Task04's separate Node/NodeCodec provenance proof, not a generic assumption that arbitrary typed-node raw spelling equals source text. The directed preparation test's DocumentNode codec explicitly opts in through `rawContentFollowsSource`.

### Cross-version line view revision

`LineIndex.bindEditableSource(version)` now binds an immutable rope line view in O(1), and `isEditableView` lets ParseSession skip redundant `recordSourceLine` appends. In view mode, `add` rejects, while `lineAt` obtains only the requested content and its exact raw-byte/raw-rune endpoints from the rope. Snapshot and restore keep/replace the immutable view reference in O(1), including an old view after width/CRLF edits; the engine can then bind the current accepted target in O(1). No edit rebuilds a whole line index. View `size` is computed on demand from rope lineCount and the EOF coordinate's UTF-16 column (O(log source) for the concrete rope); it never calls `lineAt` or copies a possibly huge final line. Neither checkpoint capture nor restore evaluates it. `lines()` remains an explicit output-sized export.

Empty input has zero recorded parser lines. A trailing line ending does not expose the rope's final synthetic empty editor position as an additional parsed line; multiple actual empty terminated lines remain present. CRLF endpoints use the rope's exact raw Unicode-rune counts (CR and LF count separately), and lone CR follows the rope's line-ending rules. The legacy flat LineScanner path is unchanged, including its historical newline accounting.

## Lifetime requirement for the engine

A tree snapshot's source version does **not** describe the birth epochs of reused raw anchors. A v128 tree can still contain raw nodes born in v0. The engine must retain each reachable birth epoch or a conservatively minimal reachable epoch from persistent summaries, plus old user snapshots, checkpoints, transactions, and external anchors. The source layer cannot infer those roots. This implementation deliberately does not auto-prune on every accepted edit or claim unchanged old anchors can be reclaimed.

Rope versions themselves remain immutable roots held by callers. An epoch lease preserves delta reachability; it does not duplicate or centrally register old roots. Releasing an epoch and pruning removes its cross-version mapping promise while an independently held old root can still read its own bytes.
